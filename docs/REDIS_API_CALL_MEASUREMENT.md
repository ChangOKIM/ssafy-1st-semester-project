# Redis 시세 캐시 외부 API 호출량 계측

## 외부 API와 기존 캐시 분석

| 외부 API | 데이터 | 호출 시점 | 변경 전 저장·캐시 |
|---|---|---|---|
| KRX | 코스피 종목 마스터 | DB가 비었을 때 초기 1회 | MySQL |
| DART | 기업 고유번호 | 종목 초기화 | MySQL `stocks.corp_code` |
| DART | 연간·분기 재무 | DB 캐시 미스 | MySQL `stock_financials` |
| KIS | 개별 현재가 | 사용자 폴링마다 | 없음 |
| KIS | 일·주·월 차트 | 리포트 진입·기간 변경 | 없음 |
| KIS | 코스피200 시총 순위 | TOP 30 조회 | JVM 30초 |
| KIS | OAuth 토큰 | 최초·만료 1시간 전 | JVM 메모리 |
| 뉴스 | - | 구현된 호출 없음 | - |

AI 리포트와 보유 종목 진단에는 GMS의 OpenAI·Anthropic API가 사용되지만 이 계측의 금융 데이터 API 합계에서는 분리했다. 변경 전 Git 이력에 Redis 구현은 없었다.

중복 호출의 핵심은 동일 종목 현재가를 메인, 추천, 리포트, AI 리포트, 보유 종목 기능이 각자 KIS에 요청했다는 점이다. DART는 DB 미스 시에만 호출되지만, 최신 분기가 아직 공시되지 않은 경우 실패 결과를 저장하지 않아 다음 요청에서 재호출될 수 있다.

## 결론

로그인 사용자가 메인 화면의 맞춤 추천 TOP 10을 30초간 조회하는 동일한 시나리오를 100회 실행했다. 외부 HTTP 서버는 호출하지 않고 KIS 클라이언트 경계에 계측용 test double을 주입했다.

| 외부 API | Redis 미사용 | Redis 사용 | 감소 |
|---|---:|---:|---:|
| DART | 0 | 0 | 0 |
| KIS 증권사 현재가 | 3,000 | 193 | 2,807 (93.57%) |
| KRX | 0 | 0 | 0 |
| 뉴스 | 0 | 0 | 0 |
| **합계** | **3,000** | **193** | **2,807 (93.57%)** |

사용자 1명의 시나리오 1회로 환산하면 `30회 → 1.93회`, 약 `93.57%`의 감소다. After의 1.93회는 개별 사용자가 직접 일으킨 호출이 아니라, 30초당 193회의 전역 갱신 비용을 100명에게 균등 배분한 값이다.

## Before 기준

- Git 커밋: `7a51053`
- 메인 화면은 추천 10종목을 종목별 API로 조회했다.
- 폴링 주기는 10초였다.
- `[0초, 30초)` 구간에서 최초, 10초, 20초의 3회 조회가 발생했다.
- 사용자당 KIS 현재가 호출은 `10종목 × 3회 = 30회`였다.
- 100명의 동일 시나리오는 `30 × 100 = 3,000회`다.

## After 기준

- 스케줄러가 `stock_info`의 코스피 주요 193종목을 30초마다 갱신한다.
- 시세 API와 AI 리포트는 KIS를 직접 호출하지 않고 Redis의 현재 스냅샷만 읽는다.
- 100명의 사용자 요청이 발생해도 사용자 요청으로 인한 KIS 현재가 호출은 0회다.
- 대신 30초 측정 구간의 전역 스냅샷 갱신 1회에서 193회가 발생한다.
- Redis 조회 300회는 외부 API 호출에 포함하지 않았다.

## 캐시 워밍과 정상 서비스

| 구분 | KIS 호출 | 사용자 요청 KIS 호출 |
|---|---:|---:|
| Redis 최초 워밍 | 193 | 0 |
| 워밍 후 30초 정상 운영 | 193 | 0 |

워밍 후에도 시세 신선도를 위한 백그라운드 호출은 계속 발생한다. 다만 이 비용은 사용자 수와 관계없이 30초당 193회로 고정된다.

## 부가 지표: 브라우저에서 백엔드로의 요청

메인 추천은 종목별 10개 요청을 일괄조회 1개 요청으로 변경했다. 동일한 100명·30초 시나리오에서 백엔드 시세 API 요청은 `3,000회 → 300회`, 즉 `90%`가 줄어든다. 이 지표는 KIS 외부 API 호출량과는 구분한다.

## 실행 방법과 실행 결과

```bash
cd backend
./gradlew test --tests com.ssafy.dartservice.stock.StockPriceApiCallMeasurementTest
```

실제 테스트 출력:

```text
MEASUREMENT users=100 before=3000 after=193 reduced=2807 rate=93.57%
```

테스트는 `stock-sectors.json`을 읽어 실제 갱신 대상이 193종목인지 검증한다. 만료된 API 키나 외부 서버 상태에 영향을 받지 않도록 `StockPriceProvider` 경계에 계측용 구현체를 사용했다. 따라서 이 결과는 실서버 트래픽 로그가 아니라 **동일 시나리오 자동화 테스트에서 외부 API 호출 경계를 계측한 결과**다.

## 감소 이유

Before에는 사용자·화면·종목별 폴링이 모두 KIS 호출로 연결됐다. After에는 전역 스케줄러만 KIS를 호출하고 모든 사용자가 완성된 하나의 Redis 스냅샷을 공유한다. 그 결과 외부 API 호출량은 사용자 수에 비례하지 않고 갱신 대상 193종목에 따라 고정된다.
